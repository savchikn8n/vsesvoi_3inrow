# "Угольная башня" Design

## Цель

Добавить вторую игру внутри текущего Telegram Mini App без отдельного проекта, повторной авторизации и риска для существующих профилей, рекордов и баланса ладошек.

"Угольная башня" - полноэкранная игра на реакцию и балансировку в духе Tower Bloxx: игрок строит башню из кубиков кальянного угля. Текущий match-3 остается production-режимом для обычных игроков, пока новая игра тестируется в alpha GameHub.

## Safety Rules

- Не сбрасывать и не пересчитывать `profiles.best_score`, `profiles.clap_balance`, покупки, подарки или скидки.
- Все backend/database изменения для второй игры должны быть additive.
- Общие Telegram auth, профиль, clap economy, shop, dashboard и runtime config остаются едиными.
- Новая игра должна иметь стабильный `game_key = 'coal_tower'`.
- Match-3 должен продолжать работать как сейчас под `game_key = 'match3'`.

## Core Gameplay

Игровая сцена занимает весь экран.

Старт:

- На поверхности стоит первый кубик угля.
- Сверху появляется следующий кубик на тонкой черной нитке.
- Позже нитку можно заменить фирменным мундштуком заведения без изменения механики.

Ход:

- Подвешенный кубик плавно раскачивается влево и вправо.
- По тапу игрок отпускает кубик.
- Кубик падает на верхний кубик башни.
- Если горизонтальное соприкосновение с нижним кубиком составляет 35% или больше площади опоры, кубик считается успешно установленным.
- Если соприкосновение меньше 35%, кубик падает и игра заканчивается.

Сессия:

- Сессия бесконечная, до первого провала.
- Нет кулдаунов.
- Нет искусственного замедления.
- Сложность растет за счет амплитуды раскачивания.

Сложность:

- Базовая амплитуда комфортная для первых блоков.
- Каждые 15-20 успешно поставленных блоков амплитуда увеличивается.
- Скорость и период раскачивания можно оставить стабильными в MVP, чтобы сложность росла предсказуемо.

Камера:

- Пока башня ниже половины экрана, камера остается в стартовой зоне.
- Когда башня занимает больше половины экрана, камера начинает центрировать последний успешно упавший кубик.
- Камера поднимается плавно и держит верх башни, подвес и зону падения видимыми.

## Scoring And Rewards

Основной счет - количество успешно установленных кубиков.

Начисление ладошек:

- 1 ладошка за каждые 10 успешно установленных кубиков.
- Начисление происходит по завершении принятой сервером сессии.
- Сервер начисляет только дельту, подтвержденную validation для `coal_tower`.

Рекорды:

- У игры должен быть отдельный record/high score для `coal_tower`.
- Общий профиль и баланс остаются общими.
- Leaderboard может быть отдельным по `game_key`; общий hub-рейтинг не нужен для MVP.

## Visual Direction

MVP визуально векторный и минималистичный.

Что фиксируем сейчас:

- Кубики угля читаются как темные кубы.
- Нитка тонкая и черная.
- Сцена полноэкранная, без карточного фрейма вокруг игры.
- UI поверх сцены минимальный: счет блоков, ладошки за текущую сессию, выход/пауза при необходимости.

Что откладываем:

- Финальный фирменный стиль.
- Ручной эталонный дизайн.
- Замена нитки на фирменный мундштук.
- Полировка анимаций, звука и микровзаимодействий.

## Alpha GameHub Dev Mode

Пока игра разрабатывается, обычные игроки видят текущий стандартный match-3 интерфейс.

Для тестирования нужен отдельный developer/tester mode внутри уже открытой игры:

- На логотип "Все Свои: Угольная башня" нужно тапнуть 5 раз.
- После этого открывается password modal.
- Пароль проверяется через серверную функцию, аналогично текущему dev-входу на техпаузе.
- После успешного входа текущая page load показывает alpha GameHub.
- Dev mode не должен сохраняться между перезагрузками WebView.
- Dev mode не должен менять schema, профиль или баланс сам по себе.

Alpha GameHub должен позволять тестировать:

- будущий интерфейс выбора игр;
- запуск "Угольной башни";
- возврат к текущему match-3;
- будущий второй слайд главного меню, когда UX/UI редизайн будет утвержден.

## Backend And Validation

Приватный репозиторий полезен как снижение риска реверс-инжиниринга, но не является античитом. Начисление ладошек и рекорды должны опираться на серверную проверку.

Для `coal_tower` validation должна быть server-authoritative с самого начала:

- `game-session-start` выдает `session_id`, `game_key`, seed, rules version и параметры раскачивания.
- Клиент отправляет последовательность отпусканий кубика: индекс блока, время/phase отпускания и компактные telemetry поля.
- Сервер пересчитывает положение подвеса, падение и overlap по тем же правилам.
- Сервер принимает только префикс ходов до первого провала.
- Сервер возвращает подтвержденные `blocksPlaced`, `clapsEarned` и validation status.

MVP validation может быть упрощенной, но должна проверять:

- session принадлежит текущему Telegram user;
- `game_key = 'coal_tower'`;
- количество ходов не превышает физически возможное за elapsed time;
- release phase соответствует серверной swing model;
- overlap каждого блока соответствует порогу 35%;
- claps earned равны `floor(acceptedBlocks / 10)`.

## Implementation Shape

Рекомендуемая структура:

- `src/games/match3/*` - постепенный перенос текущей match-3 логики, без обязательного большого рефакторинга на первом шаге.
- `src/games/coal-tower/*` - новая чистая игровая логика, правила и renderer.
- `src/game/core/*` - оставить существующие shared match-3 core modules до планового переноса.
- `game.js` - временно может остаться shell/orchestrator, но новые правила `coal_tower` не должны разрастаться внутри него без границ.

Backend:

- расширить game sessions additive-полями или таблицами, достаточными для `game_key`;
- не ломать текущие match-3 sessions;
- оставить `verify_jwt = false` для Telegram Mini App Edge Functions и проверять Telegram init data внутри функций.

## MVP Boundaries

Входит в MVP:

- page-load-only dev/tester GameHub;
- полноэкранная playable версия "Угольной башни";
- swing, tap-to-drop, overlap threshold, fail state;
- камера, поднимающаяся за башней;
- начисление 1 ладошки за 10 подтвержденных блоков;
- server-authoritative validation для начислений.

Не входит в MVP:

- финальный визуальный дизайн;
- фирменный мундштук вместо нитки;
- общий hub-рейтинг;
- cooldowns, daily limits, energy mechanics;
- сложные achievements;
- production rollout для всех игроков без отдельного подтверждения.

## Open Decisions Before Implementation

- Точный парольный endpoint для GameHub: переиспользовать текущий `maintenance-dev-auth` или выделить нейтральный `dev-auth`.
- Точные параметры swing model: стартовая амплитуда, максимум, период, прирост каждые 15 или 20 блоков.
- Нужна ли кнопка pause/exit в первой alpha или достаточно выхода через shell.
- Где хранить per-game record: отдельная таблица records keyed by `game_key` или additive поля в existing sessions/leaderboard path.
